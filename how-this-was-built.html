The Approach: Stream of Consciousness Project Management

Travis's project management strategy can be best described as "throwing ideas at an AI like he's ordering at a drive-through that never closes." He would fire off a new feature request mid-sentence while the previous one was still baking. The AI would be halfway through building a vendor comparison table when a new message would arrive: "oh and also what about medical doctors" — like a child who remembers they also wanted chicken nuggets after the car has left the drive-through.

The session transcript reads like a group text where one person is having three conversations simultaneously, except the other person is an AI with infinite patience and a slightly concerning willingness to comply.

Timeline of Events

Phase 1: The Vision
"Build me a multi-page training site." Normal request. Reasonable scope. A professional would have stopped here, made a plan, and executed. FINE
Phase 2: The Expansion
"Each use case should be flagged with what's appropriate and inappropriate." Still reasonable. Then: "include which services are safe for calendar and email and meetings." Then: "btw what are zoom, webex, granola using? what are medical doctors using?" Four new research projects launched mid-build. SCOPE CREEP
Phase 3: The Reckoning
"How much of this should be trimmed as AI slop?" The builder suddenly becomes the critic. Reviewed the AI's work, correctly identified the filler, then said "yes trim" like a surgeon who designed the patient. SELF-AWARE
Phase 4: The Avalanche
Within minutes of each other: "what tool can I transcribe video with?" / "highlight how feedback is training data" / "what does Claude Code do? is it ethical on Pro plan?" / "create deep dive pages for Microsoft and Google with costs" / "create a submission page for vendor agreements" / "create a handover guide" / "create a page roasting me." Seven requests. Some of them arrived while the AI was still writing code for the previous one. RAPID FIRE
Phase 5: The Meta-Request
"Create a page politely roasting my use of Claude Code." The man asked the AI to roast him. On his own training site. For an audience of defense attorneys. GALAXY BRAIN

Travis's Development Strategies, Rated

1. The Firehose Method SUS

Why send one message when you can send five while the AI is still processing the first? The theory appears to be that if you throw enough requests at the wall, some of them will stick. This is technically correct. It is also how you end up with a site that has more pages than a Russian novel and a nav bar that doesn't fit on a phone screen.

2. Research By Ambush YIKES

"What are medical doctors using in patient consults and what are those DUA and enterprise terms? ZDR required?" This message was sent while the AI was building a use-cases page. It required launching four background research agents, three of which failed because they couldn't access the web (because the user had denied those permissions earlier), which meant the AI had to redo the research itself. Classic.

3. The Trim-Then-Expand Paradox GALAXY BRAIN

Step 1: Build a bunch of content. Step 2: Ask the AI to identify the slop. Step 3: Trim aggressively. Step 4: Immediately request three new pages of content. This is either brilliant iteration or a perpetual motion machine for content creation. Either way, the AI's context window is crying.

4. The Meta-Demo Strategy ACTUALLY SMART

Building the AI ethics training site with AI is genuinely clever. "This entire site was built with Claude Code" is a better demo than any slideshow. The audience gets a working product AND proof that AI can do real work. The roast here is that it took two multi-hour sessions and approximately 47 interrupted tasks to get here, but nobody needs to know that.

How a True Professional Would Have Done This

What Travis Did

Wrote a site plan, then immediately deviated from it. Built one massive 2,245-line HTML file, then decided to split it into pages. Realized the content was bloated, trimmed it, then added more. Typed requests mid-build. Used the AI as a combination research assistant, web developer, project manager, and sounding board, simultaneously.

What a Professional Would Do

Write a complete specification. Design wireframes. Set up a proper build system (React, Astro, or at minimum a shared CSS file). Use a component library. Have a content calendar. Write the copy first, then build the site. Review once, deploy once. Never send seven messages in five minutes. Never ask the AI to roast them.

The Professional's Architecture

Travis's Architecture

Seven standalone HTML files, each with its own copy of the CSS. No shared components. No build step. Each file is a fully self-contained 500-2000 line document. To change the nav bar, you edit seven files. To change a color, you edit seven files. This is how websites were built in 2004.

The Elegant Solution

Astro or 11ty static site generator. Shared layout component. CSS variables in one file. Markdown content files. Build step produces static HTML. Deploy to GitHub Pages with one push. Change the nav once, it updates everywhere. Change a color once, it propagates. This is how professionals ship.

The Professional's Design

Travis's Design Philosophy

"Make it look like the other things I built." CSS copied from previous projects. Spec grids and tool comparison rows everywhere. Every page looks the same because every page uses the same six components arranged differently. The design language is "corporate training manual that learned one cool border-radius trick."

The Beautiful Version

A design system with actual thought behind it. Typography hierarchy. Proper spacing scale. Color palette with semantic tokens. Dark mode toggle. Micro-interactions that feel intentional. A homepage that doesn't look like a Jira board. The risk matrix as an interactive data visualization, not a table with colored backgrounds. Animated transitions between scenarios. This site could be beautiful. Instead, it is competent.

In Travis's Defense

Here's the thing nobody says about the "professional" approach: it would have taken three weeks, a design agency, and a five-figure budget. Travis built a working, useful, content-rich training site in two sessions with an AI tool. It has:

  • Seven pages of original, researched content
  • A vendor comparison covering 15+ tools with real pricing
  • An interactive risk matrix with scenario walkthroughs
  • A client-side agreement analyzer that works offline
  • 47+ ethics opinions with source links
  • Working print stylesheets
  • Mobile-responsive layouts
  • No dependencies, no build step, no server required

The "professional" version would be prettier. This version exists. That's the whole point of the training: AI tools are practical right now, for real work, even if the process is messy. Especially if the process is messy.

Also, he correctly identified the AI slop before the audience would have. That's the competence bar: not "produce perfect work," but "review AI output critically and fix it." Which is exactly what Missouri Opinion 2024-11 asks attorneys to do.

The Real Lesson for the Audience

This is how AI coding actually works in practice. You don't write a perfect specification and receive a perfect product. You iterate. You change your mind. You discover new requirements mid-build. You ask the AI to research something it wasn't expecting. You review the output, trim the garbage, and keep going. The messy process is the real process. If someone shows you a demo and says "AI just built this perfectly on the first try," they are lying or they edited the recording.
